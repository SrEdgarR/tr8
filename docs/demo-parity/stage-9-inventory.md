Nota posterior: las acciones masivas que aquí figuraban como pendientes se
incorporaron en la [etapa 10](stage-10.md). Las tablas conservan el inventario
histórico al cierre de la etapa 9.

Revisión de fuentes del 28 de octubre de 2026. Referencias:
[demo original de Gr8r Studio](https://gr8r-taskmanagement.vercel.app/) y
[repositorio original](https://github.com/gr8rstudio/gr8r-studio/).
Se conserva su atribución. Este inventario compara capacidades; no certifica
igualdad visual ni incorpora nuevas funciones.

## Evidencia y alcance

La demo respondió HTTP 200 y sirvió `index-BhWzXQlV.js` (357.788 caracteres).
Su bundle conserva las entradas de Perfil, Ayuda, Timeline, Archivos, sesiones,
facturación y el texto explícito de prototipo. El lector web no pudo abrirla;
la comprobación HTTP y el código legado local permiten identificar funciones,
pero no sustituyen recorrer sus pantallas en un navegador. No se interactuó
con cuentas ni datos de producción para este inventario.

TR8 carga React desde [index.html:20](../../index.html#L20). Las páginas
JavaScript originales permanecen como referencia; su presencia en el repositorio
no las convierte en funciones activas de React. Las etapas
[1](stage-1.md), [2](stage-2.md), [3](stage-3.md), [4](stage-4.md),
[5](stage-5.md), [6](stage-6.md), [7](stage-7.md) y [8](stage-8.md)
documentan sus entregas y verificaciones. Sus apartados históricos de «pendiente»
describen el estado de cada entrega, no el inventario actual.

**Real** significa que la interfaz actual tiene una operación/repositorio de
persistencia; no que este documento vuelva a ejecutar todos sus flujos.
**Parcial** significa que existe una capacidad útil pero falta una variante
identificable de la demo. **Intencional** identifica una decisión de TR8.
**Simulado** identifica controles locales o contenido ficticio de la demo.

## Criterio de cierre

Las secciones principales de navegación ya tienen implementación operativa en
React; siguen existiendo variantes funcionales, preferencias y utilidades de la
demo pendientes. No se declara paridad completa ni se presenta este inventario
estático como una revisión visual de todas las pantallas.

El orden posterior recomendado es operaciones masivas y recurrencia con sus
contratos, perfil, subtareas/adjuntos, variantes de calendario y preferencias,
y finalmente comodidad visual/ayuda. Correo, nuevas altas, MFA, facturación y
ampliación de MCP requieren decisiones y entregas propias. Ningún punto exige
cambiar ahora los planes gratuitos, importar datos de demo, modificar los datos
actuales o desactivar controles de acceso.
